# make-knowledge-cards

把一篇文章、一段笔记或一份讲稿，变成 **5–8 张可以直接用来复习的知识卡片**。

## 它解决什么问题

读长文时，真正有用的往往只有几个点，但它们散落在背景介绍、重复强调和例子中间；手动整理又容易走两个极端——
整段照抄（卡片变成原文的复印件），或者凭印象补全（写出原文没有的东西）。

这个技能把"提炼"这件事固定成一套可检查的流程：**先找候选知识点，再去重合并，然后按重要性筛到 5–8 条，
最后逐条自检每一句话是否能回到原文**。产出是结构统一、可以背、可以自测的卡片，而不是一篇更短的摘要。

## 主要功能

- **5–8 张，一卡一点**。一张卡片只讲一个知识点，标题即结论或可检索的名称，不写"背景""概述"这类空标题。
- **固定四段结构**。每张卡片都有：标题、核心知识（一句话）、简明解释（2–4 句，原文过短时 1–2 句）、
  例子或自测问题。
- **去重与合并**。开头总述、结尾总结、同一意思的反复强调、同一例子的多次使用，只保留一条；
  术语定义（如"脏读""BDNF"）并进相关卡片的解释，不单独占卡片名额。
- **不编造**。原文没有的定义、数字、因果、例外、案例一律不写；解释可以更通俗，但事实边界就是原文。
- **不凑数，也不过度合并**。原文只够 3 个知识点就只给 3 张并说明原因；反过来，合并后不足 5 张要先检查
  是不是把独立知识点硬压进了一张卡。
- **观点与事实分开**。评价、预测、促销信息不进卡片；整篇是评论、社论或建议类文章时，核心知识统一加
  `作者主张：` 前缀，避免把个人观点读成事实。
- **语言跟随原文**。中文进中文出、英文进英文出；英文输出时标题行、来源行和字段名一起翻译
  （`Knowledge Cards` / `Source` / `Core knowledge` / `Explanation` / `Example` / `Self-test`）。
- **多种输入形态**。粘贴文本、本地 `.md` / `.txt` 文件；多份来源分组输出、各自编号；
  超过 1 万字的文档先分节再做跨节去重；表格按"每行是不是独立概念"决定拆开还是合并。
- **默认在对话里输出**，只有明确要求"保存到文件"时才写入文件（如 `cards.md`）。
- **零依赖**。整个技能只有 `SKILL.md` 和 `agents/openai.yaml` 两个文件，不含脚本，不装依赖，不联网。

## 适用范围

| 支持 | 不支持 |
| --- | --- |
| 对话里粘贴的文本 | 网页 / URL（不抓取、不渲染） |
| 本地 `.md` / `.txt` 文件 | PDF、DOCX、图片、音频、视频 |
| 中文、英文及其他自然语言 | 图形界面、截图、拖拽上传 |

给的是 URL 或非 `.md` / `.txt` 文件时，技能会停下来说明只处理文本，请对方粘贴正文或另存为文本，
不会假装读过没有读到的内容。

## 目录

```
skills/make-knowledge-cards/
├── SKILL.md            # 全部工作规范：流程、卡片模板、去重与自检规则
└── agents/openai.yaml  # 界面元数据：显示名、一句话说明、默认提示词
```

## 安装方法

把整个 `skills/make-knowledge-cards/` 目录复制到你的 agent 的 skills 目录：

- 按 `skills/<技能名>/SKILL.md` 查找技能的客户端：把 `skills/make-knowledge-cards/` 放进它的 skills 根目录。
- Claude Code：复制到 `~/.claude/skills/make-knowledge-cards/`。
- 支持 `agents/openai.yaml` 的宿主：目录一起复制，界面里会显示名称、简介与默认提示词。

没有依赖、没有构建步骤：两个文件放对位置就能用。

## 使用方法

**1. 粘贴文本**

```
用 make-knowledge-cards 把下面这段做成知识卡片：

<粘贴正文>
```

**2. 给文件路径**

```
用 make-knowledge-cards 处理 tests/fixtures/01-popular-science-zh.md
```

**3. 需要落盘时**

```
用 make-knowledge-cards 处理 article.md，结果保存到 cards.md
```

默认卡片直接输出在对话里；只有说"保存到文件"时才会写文件。一次给多份来源时，技能会逐份处理、
各自从 1 编号、用 `---` 分隔；要"每节都出卡片"而不是整篇 5–8 张，也需要明确说明。

## 输入输出示例

### 示例 1：粘贴一段短文（信息只够 2 张）

输入：

> 睡眠不足会影响记忆。人在深度睡眠时，大脑会把白天学到的东西从海马体转移到皮层，这个过程叫记忆巩固。
> 所以熬夜复习往往效果不好：你记住了，但没存住。咖啡因只能暂时压制困意，不能替代深度睡眠。

输出：

```markdown
# 知识卡片：睡眠与记忆

来源：粘贴文本 ｜ 共 2 张

原文可提炼的独立知识点只有 2 个，未凑数。

## 1. 深度睡眠完成记忆巩固

**核心知识**：深度睡眠期间，大脑把白天所学从海马体转移到皮层，这个过程叫记忆巩固。

**简明解释**：记忆先暂存在海马体，深睡时再搬运到皮层长期保存。缺了这一步，白天记住的内容存不住，
所以熬夜复习效果往往不好。

**例子**：熬夜复习——内容在白天看过，但没经过深度睡眠的巩固，"记住了，但没存住"。

## 2. 咖啡因不能替代深度睡眠

**核心知识**：咖啡因只能暂时压制困意，不能产生深度睡眠带来的记忆巩固。

**简明解释**：困意被压住不等于记忆已被巩固。咖啡因解决的是"困"，记忆巩固发生在深度睡眠中，
两者不能互相替代。

**自测**：熬夜后喝咖啡提神，能补上记忆巩固这一步吗？
```

注意"睡眠不足会影响记忆"没有单独成卡：它和"记忆巩固"是同一件事，被并入了第 1 张；
只有 2 个独立知识点，就只给 2 张并说明未凑数，没有为够到 5 张而拆句。

### 示例 2：一份新闻稿（篇幅长，知识点少）

输入 `tests/fixtures/03-news-product-zh.md`（约 500 字的产品发布会报道），输出 **5 张卡片**：

```markdown
# 知识卡片：LightInk 3 阅读器

来源：03-news-product-zh.md ｜ 共 5 张

## 1. 电子墨水屏靠反射环境光成像，代价在刷新与色彩
## 2. 硬件规格：10.3 英寸 300 ppi 屏，标配 4096 级压感笔
## 3. 每天读 1 小时，续航 6 周
## 4. 售价 2499 元，10 月 15 日发货，首发限量 200 台
## 5. 前两代产品累计销量超过 40 万台
```

分析师那句"今年最值得买的阅读器，没有之一"、嘉宾"五年内取代纸书"的预测、以及"预约送保护套"的
促销信息都没有进卡片：它们是评价和推销，不是知识。"发布会没有公布供应商"这类缺失信息也不成卡。
完整输出见 [`tests/results/03-news-product-zh.md`](tests/results/03-news-product-zh.md)。

## 它是怎么保证质量的

`SKILL.md` 里有八条硬性规则和一份输出前自检清单，其中最关键的四个约束是：

| 规则 | 含义 |
| --- | --- |
| 不编造 | 解释可以更通俗，但事实边界就是原文；拿不准就省略 |
| 一卡一点 | 一张卡片一个知识点；"既讲 A 又讲 B"要拆开或只留主线 |
| 去重 | 核心知识相同就算重复；术语定义并入相关卡片，不单独占位 |
| 不凑数 | 不足 5 条就少给并说明；也不许用"信息密度有限"掩盖过度合并 |

另外几条容易踩的坑也写进去了：观点与事实分开、原文有误不擅自纠正（只标注"原文前后不一致"）、
表格按"每行是否独立概念"决定拆分还是合并、超长文档先分节再跨节去重。

## 测试

`tests/` 下是 6 份不同体裁的输入，每份都埋了对应的陷阱：

| Fixture | 体裁 | 预期卡片数 | 陷阱 |
| --- | --- | --- | --- |
| `01-popular-science-zh.md` | 中文科普 | 6 | 首尾重复、段末广告 |
| `02-howto-cache-en.md` | 英文技术指南 | 5–7 | 应输出英文；代码块不算知识点 |
| `03-news-product-zh.md` | 新闻稿 | 3–5 | 篇幅长但知识点少；观点、促销、缺失信息 |
| `04-academic-cognitive-load-zh.md` | 学术摘要 | 5–8 | 候选约 10 条，必须取舍 |
| `05-tiny-note-zh.md` | 一句话 | 1–2 | 绝不能凑到 5 张 |
| `06-table-isolation-zh.md` | 表格速查 | 5–7 | 既不能压成 1 张，也不能拆成名词表 |

判定口径、三轮迭代的发现与改动、最终 6 份输出的通过记录见 [`tests/README.md`](tests/README.md)
与 `tests/results/`。复现方式：把 `SKILL.md` 和任意一份 fixture 交给一个只读这两个文件的 agent，
看它是否落在预期区间、是否踩陷阱。

## 校验

用官方 `skill-creator` 的 `quick_validate.py` 检查 `SKILL.md` 的结构：

```bash
python quick_validate.py skills/make-knowledge-cards
# Skill is valid!
```

在中文 Windows 上如果报 `UnicodeDecodeError: 'gbk' codec`，是脚本按系统默认编码读文件导致的，
加 `-X utf8` 或设置 `PYTHONUTF8=1` 即可：

```bash
python -X utf8 quick_validate.py skills/make-knowledge-cards
```

## 局限

- 不抓网页、不解析 PDF/DOCX/图片/音频，只处理文本与本地 Markdown/TXT。
- 不做事实核查：卡片忠实于原文，原文错了卡片也可能跟着错（会标注"原文前后不一致"，但不替作者改）。
- 卡片数量默认在 5–8 张；需要"每节都出卡片"时要明确说明。
- 不做图形界面：没有上传、拖拽、预览，只有文本进、卡片出。
