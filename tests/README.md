# 测试集

每个 fixture 都是一份真实形态的输入，并刻意埋了对应的陷阱。判断输出是否合格，看三件事：
**卡片数量是否落在预期区间**、**必须覆盖的知识点是否都在**、**有没有踩陷阱**。

`tests/results/` 里是每个 fixture 在最终版本上的实际输出，文件头记录了输入、版本和结论。

## 判定口径

- **硬伤（不合格）**：编造原文没有的事实/数字；把观点当知识；为了凑数拆句或灌水；卡片数超出 5–8 而原文并非不足。
- **可接受**：两张相关卡片合并成一张（例如把"压力升高皮质醇"和"运动降低皮质醇"合成一张），只要知识点没丢。
- **可接受**：`例子` 与 `自测` 的取舍不同，只要内容都能在原文找到依据。
- **可接受**：卡片数在区间内的浮动（例如 01 出 5 张还是 6 张），取决于"支撑性定义要不要单列"的判断。

## 测试方式

把 `SKILL.md` 和一份 fixture 交给一个**只读这两个文件**的 agent（不告诉它预期答案、不提供本仓库其他内容），
让它按技能输出卡片，再对照上表逐项检查。这样能同时验证"技能写得够不够明确"和"输出质量"。

另外三位测试者独立提出的歧义（合并去重后）：

1. 「列表/表格」要求一行一张还是合并成一张，与"一卡一点"直接冲突；
2. 术语定义（脏读、BDNF、图式）算不算独立知识点，没有规则；
3. "原文有具体例子、数据 → 用例子"会让数据型卡片用例子复述核心知识；
4. 观点、预测、促销、缺失信息（"没有公布供应商"）没有纳入/排除标准；
5. 模板标题有三种写法，`标题：一句结论` 与示例不一致；
6. 英文输入时，模板里的中文标签要不要翻译，没有说明；
7. 多来源时编号从 1 重来还是继续，`共 N 张` 是每组还是合计，没有说明；
8. 主题标题从哪来、要不要算"可溯源"，没有规则。

### v2：针对上述 8 条改写

- 新增「纳入 / 排除」表：观点、预测、促销、缺失信息明确排除；整篇是评论时按"作者主张"标注。
- 新增「术语定义默认不单独成卡」，并给出"支撑性定义"的判定问句。
- 表格/列表改为两分支：每行是独立概念 → 一行一张；只是并列例子/同义建议 → 合并成分类卡。
  判断方法："删掉这行会不会丢一个独立知识点"。
- 例子规则加约束：必须独立于核心知识，只是复述就改用自测。
- 数量不足的措辞改为"原文可提炼的独立知识点只有 N 个，未凑数"，并加一条反向检查：
  **合并后不足 5 张，先检查是不是过度合并**（避免把"过度合并"说成"信息密度有限"）。
- 统一标题写法为 `## N. <标题>`，并规定标题不能是"背景/概述"。
- 增加语言适配：英文用 `Knowledge Cards` / `Source` / `Core knowledge` / `Explanation` /
  `Example` / `Self-test`；多来源用 `---` 分隔、各自从 1 编号。
- 规定主题从原文标题或首段归纳，不自行加判断。

v2 复测：03 → 4 张（观点已剔除，合格）；06 → 8 张（不再压缩，但多出"脏读/不可重复读/幻读"
三张纯名词卡，像名词表）；02、05 仍然合格。

- 术语定义默认不占卡片名额，写进相关卡片的简明解释；只有全文讨论对象本身才可单列，最多 1–2 张。
