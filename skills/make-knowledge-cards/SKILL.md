# 制作知识卡片（make-knowledge-cards）

把一段文本或一个本地 Markdown/TXT 文件，提炼成 **5–8 张知识卡片**。每张卡片只讲一个知识点，
结构固定：标题、核心知识、简明解释、例子或自测问题。

这份文档就是全部工作规范。按"处理流程"做，输出前用"自检"逐条检查。

## 适用范围

| 支持 | 不支持 |
| --- | --- |
| 用户在对话里粘贴的文本 | 网页/URL（不抓取、不渲染） |
| 本地 `.md` / `.txt` 文件 | PDF、DOCX、图片、音频、视频 |
| 中文、英文及其他自然语言 | 图形界面操作、截图、拖拽上传 |

如果用户给的是 URL，或给的文件不是 `.md` / `.txt`：**停下来说明本技能只处理粘贴文本和本地
Markdown/TXT**，请对方把正文粘贴进来，或另存为 `.md` / `.txt` 再处理。不要尝试抓网页、不要
假装读过没有读到的内容。

## 处理流程

### 1. 取到原文

- **粘贴的文本**：直接使用，不改写、不补全。
- **文件路径**：用文件读取工具（`read`）读全文。相对路径按当前工作目录解析；拿不准就用绝对路径。
  文件很长时也要读完，不能只读开头就下结论。
- 读不到文件（不存在、无权限、编码异常）：如实说明，请用户确认路径或改为粘贴，不要猜测内容。

在卡片组开头写两行：主题标题行，以及 `来源：<文件名> ｜ 共 N 张`。文件名只写文件名，不写整条路径。

### 2. 通读，标记候选知识点

逐段扫，把承载知识的句子标出来。一个**独立知识点**算一条候选（同一件事的几种说法仍算一条）。

| 纳入 | 排除 |
| --- | --- |
| 定义与分类：是什么、分几类 | 背景铺垫、行业套话、时间线寒暄 |
| 机制与因果：为什么、靠什么起作用 | 褒贬评价："最值得买""没有之一" |
| 方法与步骤：怎么做、按什么顺序 | 预测："五年内会取代……" |
| 判断标准、阈值、例外、误区 | 促销与导购：赠品、预约优惠、购买链接 |
| 关键数据与可验证事实：规格、价格、数值、日期 | "原文没有公布/未说明"的缺失信息 |
| 反直觉结论、作者给出的明确论断 | 过渡句、重复强调、纯情绪表达 |

**引述他人观点默认排除**。若整篇本身就是评论/社论，改为提炼"作者的主张 + 他给出的理由"，
并在核心知识开头写 `作者主张：`，让人一眼看出这是观点而非事实。

### 3. 合并与去重

判重口径：**核心知识相同就算重复**，哪怕措辞完全不同。合并后保留信息最完整的那条，
缺失的限定条件可以互相补齐，但不得补入原文没有的内容。

- 开头总述、结尾总结与中间某张卡片讲同一件事 → 并入那张卡片，不单独成卡。
- 同一个例子被反复使用 → 只留一处。
- **支撑性定义要不要独立成卡**：删掉它，主线还讲得通吗？讲不通，且它本身是一件可单独记住的事实
  （例如"睡眠分为四个阶段，深睡是其中之一"）→ 可以单列；只是名词解释、离开主点没有意义 → 并入主卡。
- **术语定义默认不单独成卡**：像"脏读""BDNF""图式""幻读"这类名词解释，写进相关卡片的
  简明解释里，不占卡片名额。只有全文讨论对象本身（文章通篇在讲的那个概念）才值得单列，
  且最多 1–2 张。宁可少一张术语卡，也不要让卡片组变成名词表。
- **相近概念不算重复**：同一主题下的不同效应、不同级别、不同策略，只要能各自成立，就是不同知识点。

### 4. 排序并筛选到 5–8 张

按"对理解主题的载重"排序，而不是按原文顺序；同一层内保持原文顺序：

1. 定义、原理、核心机制
2. 方法与可执行步骤
3. 判断标准、阈值、条件
4. 例外、误区、反直觉结论
5. 具体数据与细节

数量规则（候选数 = 独立知识点数）：

- **5–7 条**：全部收录。
- **8 条以上**：取 8 条，保留主线（定义 + 机制 + 方法 + 例外），不能因为某一节写得多就全给它。
  取舍时**先砍术语定义和解释性内容**，再砍细节；成组出现的对照关系（例如四个隔离级别）要整体保留，
  不要只留其中两三个。
- **少于 5 条**：按实际条数输出，见"数量不足时"。

覆盖要求：不能整组卡片都来自同一段。若某一节有独立知识点而完全没被收录，说明你漏了主线。

### 5. 写卡片

统一模板（Markdown，便于复制进笔记软件）：

```markdown
## 1. <标题>

**核心知识**：一句话说清这个知识点本身。

**简明解释**：2–4 句，讲清"是什么 / 为什么 / 怎么用"，用平实的语言。

**例子**：原文中的具体案例（可压缩）。
```

- **标题**：结论句或可检索的知识点名词短语，两种都行；但**不能**是"背景""概述""第三部分"
  这类空标题，也不要重复"知识卡片"四个字。
- **核心知识**：一句话，是这张卡片的答案；读完它就该知道这张卡在说什么。数据型知识
  （规格、价格、日期）直接把数字写在这里。
- **简明解释**：可以压缩、换更简单的说法、把原文的因果链拆开讲，但**不引入原文没有的机制或数据**。
  原文过短时 1–2 句即可 —— 宁短勿编，不要为了凑句数复述核心知识或补充常识。
- **例子或自测**二选一：
  - **例子**：原文里的具体案例、实验、场景、数据。**必须独立于核心知识**，不能把核心知识换个说法
    再写一遍；写完对照一下，如果例子只是在重复上一行，就改用自测。
  - **自测**：一个**只能靠原文作答**的问题（判断、问答皆可）。默认不给答案；用户要求时才加
    `参考答案：`，答案同样只能来自原文。
  - 拿不准用哪个：优先自测。自测永远不会泄露不存在的信息。

卡片之间空一行，组内编号连续。

### 6. 输出前自检

逐条核对，任何一条不过就改：

- [ ] **可溯源**：每句话都能在原文找到依据；没有新增事实、数字、人名、机构、结论。
- [ ] **一点一卡**：每张卡片只有一个知识点；没有把一张卡片写成"三合一"的合集。
- [ ] **无重复**：同一知识点的不同表述已合并；相近但不同的概念没有被压成一张。
- [ ] **例子不注水**：`例子` 里的内容来自原文，且不是核心知识的复述。
- [ ] **数量合规**：卡片数在 5–8 之间，或者原文确实不足 5 条独立知识点且已说明。
- [ ] **不凑数**：没有拆句、灌水、把背景或观点当知识点。
- [ ] **覆盖主线**：没有整组卡片只覆盖开头一段。
- [ ] **无空话**：没有"本文介绍了……""希望对你有帮助""综上所述"。

## 硬性规则

1. **不编造**。原文没有的定义、数字、因果、例外、案例，一律不写。解释可以更通俗，但事实边界就是原文。
   拿不准就省略，宁少勿假。
2. **一卡一点**。一张卡片只承载一个知识点。原文里"既讲 A 又讲 B"的长句，拆成两张，或只留主线那一个。
3. **不凑数**。信息不足时输出少于 5 张并说明；**绝不允许**为了数量拆分同义句、把背景当知识、
   或用常识补全原文。反过来，也不能用"信息密度有限"掩盖自己过度合并。
4. **只提炼，不复述**。不要逐段摘要、不要顺着原文顺序洗稿；输出的是重新组织的知识结构。
5. **语言跟随原文**。中文进、中文出；英文进、英文出。专有名词保留原文写法，结构标签一起翻译
   （见"输出格式"）。
6. **不写元信息**。除了主题行、来源行、"未凑数"说明行和卡片本身，不加前言、自我介绍、使用建议、免责声明。
7. **不做事实核查**。按原文提取，不擅自纠正；只有原文自相矛盾、且影响理解时，才在卡片末尾加一行
   `原文前后不一致。`，不要替作者改成你认为正确的版本。
8. **观点与事实分开**。评价、预测、促销不进卡片；整篇是评论时，按"作者主张"标注后再提炼。

## 数量不足时

原文只支撑 2–4 个独立知识点时：

- 在来源行下面紧跟一行：`原文可提炼的独立知识点只有 N 个，未凑数。`
- 正常输出这 N 张，不拆句、不灌水、不用常识补位。
- 末尾可选一行 `补充方向：` 说明还需要哪类信息（定义？机制？数据？）才能形成更多卡片。
  这行是**建议**，不是卡片，不得混进卡片内容。

如果合并后不足 5 张，先回头检查是不是**过度合并**：把本来独立的点硬压进了一张卡。修好这一点，
再决定是否真的属于"数量不足"。

## 边界情况

- **输入只有一两句、且没有可成卡的知识点**：直接说明"这段内容不足以提炼知识卡片"，并说明缺什么，
  不产出空卡片。
- **列表/表格类输入**：先判断每一行是不是独立概念。
  - 每行是不同概念（不同隔离级别、不同疾病、不同策略）→ **一行一张卡片**，超过 8 行时取最重要的 8 行。
  - 每行只是同一概念的例子、同义建议或并列口号 → 合并成一张"分类"卡片。
  - 判断方法：删掉这一行，是否就丢了一个独立知识点？会丢，就单列。
- **含代码**：代码块本身不算知识点。提取它解决的问题、关键约束和取舍。
- **含大段闲聊或推销**：跳过，不要写进卡片，也不要评价。
- **超长文档（1 万字以上）**：先按标题或自然段分节，再跨节做去重和排序，默认整篇给 5–8 张卡片。
  若用户明确要求"每节都要卡片"，则按节输出，每节 1–5 张，并在开头说明分节方式。
- **用户给了多份来源**：逐份处理，每份一组，各自从 1 编号，组与组之间用一行 `---` 分隔。

## 输出格式

```markdown
# 知识卡片：<主题>

来源：<文件名 或 粘贴文本> ｜ 共 N 张

## 1. <标题>

**核心知识**：……

**简明解释**：……

**例子**：……（或 **自测**：……）

## 2. <标题>

……
```

- **主题**：从原文标题或首段归纳，中文 2–12 字、英文 2–6 个词；原文有标题就直接用（去掉副标题和
  营销词），不要自己加判断。
- **结构标签和来源行一起翻译**：英文写成 `# Knowledge Cards:`、`Source: <file> | 7 cards`、
  `**Core knowledge**`、`**Explanation**`、`**Example**`、`**Self-test**`；其他语言同理。
- 默认**在对话里直接输出**。只有当用户明确要求"保存到文件"时，才写入文件（例如 `cards.md`），
  并回一句写到了哪个路径。

## 示例

输入（粘贴文本，只有两句话承载知识）：

> 睡眠不足会影响记忆。人在深度睡眠时，大脑会把白天学到的东西从海马体转移到皮层，这个过程叫记忆巩固。
> 所以熬夜复习往往效果不好：你记住了，但没存住。咖啡因只能暂时压制困意，不能替代深度睡眠。

输出：

```markdown
# 知识卡片：睡眠与记忆

来源：粘贴文本 ｜ 共 2 张

原文可提炼的独立知识点只有 2 个，未凑数。

## 1. 深度睡眠完成记忆巩固

**核心知识**：深度睡眠期间，大脑把白天所学从海马体转移到皮层，这个过程叫记忆巩固。

**简明解释**：记忆先暂存在海马体，深睡时再搬运到皮层长期保存。缺了这一步，白天记住的内容存不住，
所以熬夜复习效果往往不好。

**例子**：熬夜复习——内容在白天看过，但没经过深度睡眠的巩固，"记住了，但没存住"。

## 2. 咖啡因不能替代深度睡眠

**核心知识**：咖啡因只能暂时压制困意，不能产生深度睡眠带来的记忆巩固。

**简明解释**：困意被压住不等于记忆已被巩固。咖啡因解决的是"困"，记忆巩固发生在深度睡眠中，
两者不能互相替代。

**自测**：熬夜后喝咖啡提神，能补上记忆巩固这一步吗？
```

注意这个例子里做了什么：开头"睡眠不足会影响记忆"被并入卡片 1（与"记忆巩固"是同一知识点），
没有被单独做成一张"背景卡"；只有 2 个独立知识点，就只给 2 张，并说明未凑数。
